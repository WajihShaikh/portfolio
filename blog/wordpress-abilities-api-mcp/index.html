WordPress Abilities API and MCP: A Practical Developer Guide

A structured capability layer is becoming an important part of modern WordPress integration, whether the caller is a plugin, interface or AI assistant.

Written byWajih Shaikh

Senior WordPress Developer & Web Designer

In this articleWhat the API doesHow the pieces fitDesigning an abilityPermissionsWhen to use it

Quick answer: The WordPress Abilities API is a central registry for describing and executing site capabilities with defined inputs, outputs and permissions. Public abilities can be exposed to compatible AI clients through the WordPress MCP Adapter. The API does not bypass WordPress authorization, and sensitive actions still need server-side checks.

What problem does the Abilities API solve?

WordPress plugins have always provided functions, REST routes, hooks and commands. The challenge is discoverability. Another system may know that code exists without knowing what it does, which inputs it accepts, what it returns or who may run it.

The Abilities API, introduced in WordPress 6.9, provides a shared registry for those details. An ability can describe a task such as retrieving a site summary, checking inventory or generating a report. That metadata makes the capability easier for admin interfaces, automation systems and AI clients to discover and call correctly.

The official Abilities API lesson is the best starting point for current concepts and code.

How the WordPress AI pieces fit together

Abilities API

Defines what the site can do and the contract for doing it.

AI Client

Provides a provider-agnostic way for WordPress code to request AI model output. Plugin code can depend on the client interface rather than being tightly coupled to one vendor.

MCP Adapter

Translates eligible WordPress abilities into tools that an MCP-compatible client can discover and call. The adapter is a bridge, not a permission bypass.

The WordPress developer article From Abilities to AI Agents explains that relationship in more detail.

What makes a good WordPress ability?

  • One clear responsibility. Prefer “list low-stock products” over “manage ecommerce.”
  • Explicit input schema. Define types, required fields, limits and allowed values.
  • Predictable output. Return structured data and useful errors.
  • Permission callback. Check the current user and the specific operation.
  • Safe execution. Sanitize inputs, escape outputs and use existing WordPress APIs.
  • Limited side effects. Separate reading, drafting and publishing into distinct abilities.

Good tool design reduces ambiguity for every caller, not just AI. It also makes tests easier to write.

A simple architecture

  1. The plugin registers a narrowly scoped ability.
  2. The ability declares input and output schemas.
  3. A permission callback validates the authenticated user.
  4. The execution callback calls trusted WordPress functions.
  5. The caller receives a structured result or explicit error.
  6. Logging records only what is necessary for diagnosis and audit.

Permissions must stay outside the model

A language model can request an action. It should not decide whether that action is authorised. WordPress capabilities, application credentials and server-side validation must make that decision.

  • Apply least privilege to the connected user.
  • Require stronger confirmation for publishing, deletion, refunds or user changes.
  • Do not place API keys in prompts or ability results.
  • Protect against prompt injection in posts, products and uploaded files.
  • Limit batch size and execution frequency.
  • Return the minimum data needed for the task.
  • Provide a simple way to revoke access.

If an ability cannot be safely exposed to an untrusted script, it is not automatically safe because an AI assistant is calling it.

When should a plugin use the Abilities API?

Use it when a capability should be discoverable and reusable across interfaces or automations. Examples include diagnostics, structured content operations, reporting, product lookups or controlled site-management workflows.

Do not wrap every internal function. Private implementation details, extremely sensitive operations and simple code paths with no external caller may not benefit.

Frequently asked questions

Is the Abilities API only for AI?

No. It is a general capability registry. AI and MCP are important use cases, but admin interfaces and conventional automations can also use structured abilities.

Does an MCP client get administrator access?

Not automatically. Access follows the authenticated WordPress user and each ability’s permission rules.

Should every ability be public through MCP?

No. Expose only what is needed and safe for that interface.

Can I build an AI-powered WordPress plugin now?

Yes. WordPress provides official guidance for combining the Abilities API, AI Client and MCP Adapter, but developers should track compatibility and API changes.

Why this matters for WordPress development

The durable idea is not “add AI to everything.” It is to give WordPress capabilities clear contracts and permissions. That architecture makes integrations easier to understand, test and secure.
